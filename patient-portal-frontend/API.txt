IMPORTANT
---------

This catalog is derived from the current Spring controllers, request DTOs, response
models, service command records and gateway routes. It describes what the frontend
can call today. The live OpenAPI documents exposed through the gateway remain the
machine-readable authority and should be used to generate TypeScript types.

Several newer workflow endpoints return Map<String,Object> or void. For those, this
file records the database-shaped JSON observed in the service implementation. Those
shapes should be promoted to explicit backend DTOs before the frontend treats them
as a long-term stable contract.

1. TRANSPORT CONVENTIONS
------------------------

Default request headers:

  Accept: application/json
  Authorization: Bearer <JWT>              all protected endpoints
  Content-Type: application/json           requests with JSON bodies

Special headers:

  Idempotency-Key: <unique stable value>   patient creation, billing-account
                                            creation, and portal payments
  X-Break-Glass-Id: <UUID>                 optional FHIR Patient emergency grant
  Accept: application/fhir+json            FHIR endpoints

Formats:

  UUID       canonical UUID string
  date       YYYY-MM-DD
  time       HH:mm or HH:mm:ss
  datetime   ISO-8601; send an offset/UTC for Instant values
  decimal    JSON number; frontend must retain decimal semantics for currency

Common outcomes:

  200 OK           successful read/update or controller-default void response
  201 Created      successful creation where explicitly returned
  202 Accepted     queued notification or imported lab result
  204 No Content   patient deletion; some void endpoints currently return 200 empty
  400 Bad Request  malformed UUID/enum/date, failed bean validation, invalid state
  401 Unauthorized missing, malformed, expired or invalid bearer token
  403 Forbidden    authenticated identity lacks role/context/consent
  404 Not Found    resource does not exist
  409 Conflict     stale workflow, reused reference, safety/inventory/state conflict
  410 Gone         inactive FHIR Patient
  503 Unavailable  privacy decision service failed or returned malformed data

Spring error bodies are not yet standardized. Treat error payloads as `unknown`,
show a safe user message, and retain a request ID if supplied. FHIR errors use the
OperationOutcome shape defined below.

3. ENDPOINT CATALOG
-------------------

Every path below is the external gateway path the browser should use. `Body: none`
means no request entity. Unless marked public, supply a bearer token.

3.1 Authentication service

POST /auth/login
  Role: public. Body: LoginRequest. Result: 200 LoginResponse; 401 empty body.

GET /auth/validate
  Role: any valid token. Body: none. Header: Authorization required.
  Result: 200 empty body when valid; 401 empty body otherwise.

POST /auth/admin/users
  Role: ADMIN. Body: {email:string,password:string(min 12),role:UserRole}.
  Result: 201 {id,email,role,status}. New accounts are ACTIVE.

GET /auth/admin/users/{id}
  Role: ADMIN. Result: 200 {id,email,role,status}; 404 when absent.

PATCH /auth/admin/users/{id}/role
  Role: ADMIN. Body: {role:UserRole}. Result: 200 {id,email,role,status}.

PATCH /auth/admin/users/{id}/status
  Role: ADMIN. Body: {status:"INVITED"|"ACTIVE"|"LOCKED"|"DISABLED"}.
  Result: 200 {id,email,role,status}. Only ACTIVE accounts can log in.

3.2 Patient service

GET /api/patients
  Roles: ADMIN, CLINICIAN, REGISTRATION_STAFF. Body: none.
  Result: 200 PatientResponse[].

GET /api/patients/{id}
  Roles: same. Path: id UUID. Body: none. Result: 200 PatientResponse; 404.

POST /api/patients
  Roles: same. Header: optional Idempotency-Key. Body: PatientRequest.
  Result: 200 PatientResponse. A replay with the same key/payload is idempotent.

GET /api/patients/duplicates?name=&dateOfBirth=&phone=&email=
  Roles: same. All query fields optional; dateOfBirth is date. Body: none.
  Result: 200 PatientResponse[].

POST /api/patients/{id}/status/{status}
  Roles: same. status is a PatientResponse status enum. Body: none.
  Result: 200 PatientResponse; invalid transition may return 409.

POST /api/patients/{sourceId}/merge/{targetId}
  Roles: same. Both paths UUID. Body: none.
  Result: 200 survivor/source PatientResponse reflecting merge; conflict on invalid merge.

POST /api/patients/{sourceId}/unmerge
  Roles: same. Body: none. Result: 200 PatientResponse; conflict if no reversible merge.

PUT /api/patients/{id}
  Roles: same. Body: PatientRequest; registeredDate is optional on update.
  Result: 200 PatientResponse.

DELETE /api/patients/{id}
  Roles: same. Body: none. Result: 204 empty body.

GET /api/fhir/metadata
  Roles: ADMIN, CLINICIAN. Accept: application/fhir+json. Body: none.
  Result: 200 FHIR CapabilityStatement.

GET /api/fhir/Patient/{id}
  Roles: ADMIN, CLINICIAN plus an active consent or explicit emergency grant.
  Header: optional X-Break-Glass-Id UUID. Body: none.
  Result: 200 FHIR Patient with ETag, Last-Modified and Cache-Control:no-store;
  400/403/404/410/503 FHIR OperationOutcome where handled by this controller.

4. FRONTEND INTEGRATION NOTES
-----------------------------

  - Generate clients from the 12 OpenAPI documents, but call gateway-prefixed paths.
    Some service documents advertise direct paths; gateway routing adds /api or
    /auth as shown above.
  - Do not expose the privacy decision endpoint as an ordinary end-user control.
    It exists to support server-side FHIR authorization.
  - Do not assume a PATIENT role can safely use every endpoint whose coarse role
    annotation permits it. Platform-wide patient/facility authorization is still an
    open production gate outside the patient-portal service's ownership checks.
  - Treat all snake_case dynamic Map responses as provisional contracts. Add explicit
    backend response DTOs and OpenAPI annotations before building durable UI around
    them.
  - Render record-release downloads as files; do not insert their content into HTML.
  - Payment/claim/invoice amounts must use decimal-aware formatting and calculations.
  - Status values not declared as enums may grow. Display an unknown status safely.
  - Refresh workflow resources after a 409; do not overwrite newer server state.
  - The Swagger UI is an index of separate specs, not one merged contract. A JSON
    bundle can preserve the specs, while a true merged OpenAPI document needs schema
    namespace/collision handling.

5. CONTRACT MAINTENANCE CHECKLIST
---------------------------------

When a backend controller or DTO changes:

  1. Start the synthetic/local stack with public docs enabled.
  2. Export all OpenAPI JSON through the gateway.
  3. Compare paths, methods, required headers, schemas and status codes.
  4. Update API.txt and regenerate TypeScript types.
  5. Add/update request mocks and contract tests.
  6. Verify gateway prefix, authentication, role denial and patient context.
  7. Ensure new response bodies do not expose internal credentials, hashes or PHI
     fields beyond the workflow's minimum necessary data.
