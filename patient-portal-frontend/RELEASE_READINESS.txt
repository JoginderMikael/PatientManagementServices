PATIENT PORTAL FRONTEND - RELEASE READINESS RECORD
==================================================

Status vocabulary
-----------------
IMPLEMENTED means the control exists. VERIFIED LOCALLY means its named automated
check passed in a developer workspace. RELEASE CANDIDATE requires every automated
gate below plus the integrated deployment checks. PRODUCTION APPROVED requires all
three named approvals at the end of this record.

Automated engineering gate
--------------------------
Run from patient-portal-frontend:

  npm ci --no-audit --no-fund
  npm run release:verify
  npm run contract:check
  npm audit --omit=dev --audit-level=high

Run the public advisory query only from an organization-approved network/CI context;
it transmits dependency names and versions to the configured npm registry.

release:verify performs strict TypeScript checking, all synthetic component and
integration tests, axe checks across every role family and 320-1440px reference
widths, a production build, gzip bundle budgets, source-map rejection, and a live
runtime check of CSP/security/cache headers.

contract:check reads contracts/frontend-api-contract.json and verifies every API
operation required by the frontend against the deployed gateway OpenAPI exports.
Set API_BASE_URL for a non-local gateway. If API documentation is protected, set a
short-lived ADMIN API_TOKEN in the process environment; never put it in this file.
